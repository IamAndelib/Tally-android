# Charges — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make fees, interest and tax one thing, a **charge**, that is part of the entry it came with: offered on all
seven forms through the approved tonal card, counted as spending (a purchase's in its own category, the rest in one
grey Charges part on Home and in Summary) or, received on a lending's payment, as income; with saved data version 8.
It is the last item before the 1.4.5 release (the release gate in `docs/plans/2026-11-01-release-1.4.5.md`).

**Architecture:** A charge stays its own entry linked both ways to its entry (`feeOf` on the charge, `feeId` on the
entry), as transfer and payment fees are today; version 8 widens which entries may carry one and lets a lending
payment's charge be an `income`. One counting rule in `js/state.js` (`isSpend()` = every expense, `spendCat()` = the
part it counts in: a category or `CHARGES`) is followed by every total: `spentOn()` (widget, morning check), Home
(`js/screens.js`, `js/ring.js`), History (`js/history.js`), Summary (`js/summary.js`) and search (`js/search.js`).
One shared form part, the charge card (`chargeCard()` in `js/sheets.js`, replacing `feeField()`), with the keypad
naming its field (`js/calculator.js`), serves the transfer, payment, draw, received and spent forms (`js/sheets.js`,
`js/loans.js`). One helper makes or updates an entry's charge (`setCharge()` in `js/state.js`) so every form, edit and
the overpaid dialog keep the charge's account, date and category with its entry.

**Tech Stack:** Classic scripts in one global scope (WebView 87+), CSS in `rem`, Playwright e2e suites in `tests/e2e`,
catalogues in `l10n/web/*.json` generated into `js/i18n/` by `tools/gen_i18n.py`.

**Spec:** `docs/specs/charges.md` (draft; its section **Decisions still needed**, D1–D14, is answered by the maintainer
before the tasks that depend on it). Approved images: the design round's C-transfer, C-rows, C-home, C-summary,
C-forms, C-overpaid and the tonal card B.

## Global Constraints

- **Data safety:** the version 8 step in `migrate()` never changes an amount, account, date or balance; it ships with
  its tests in Task 1, before any screen changes; a v7 save and a v7 backup load unchanged; a v8 backup restored by an
  older version keeps every balance; the format is never changed again by a later task without a test.
- **Tally never files an entry under a category by itself:** a charge counts in its purchase's category (the user's
  pick) or in the fixed Charges part, never in the built-in Fees category, whatever it was renamed to.
- **Totals agree:** for one period and currency, Home's figure, Summary's total, History's default "spent", the widget
  and the morning check are the same number; every task that touches a total checks it.
- WebView 87: no `:has()`, `:is()`, `structuredClone`, `color-mix()`.
- Every font size in `rem`; boxes holding text use `min-height`; words wrap, never cut or shrink (`22-layout.js`).
- Every visible text through `T()` / `TH()`, keys in `l10n/web/en.json` and all eight other languages (each task
  translates its own new keys), then `python3 tools/gen_i18n.py`; never Prettier on `js/i18n/`.
- 48 dp targets; nothing by colour alone (the word "charge" / "Charges" is always beside the grey); WCAG AA contrast in
  light and dark.
- The keypad and Android's keyboard are never on screen together.
- Don't reuse existing class names for new effects.
- Every visible change matches the approved images; what the spec lists as undecided is asked, not invented.
- Commits end with only `Co-Authored-By: Claude <noreply@anthropic.com>`.
