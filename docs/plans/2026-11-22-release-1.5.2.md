# Tally 1.5.2: release plan

A point release from what the 1.5.0 reviews found: fixes and under the hood, no new screens (docs/roadmap.md).
`tallyVersion=1.5.2`, `tallyVersionCode=10502`. 1.6.0 (the Plan tab, from PR #55, and security) starts after it.
Tick a box only when its proving check has passed, in the same pull request.

**How each item is built:** as in docs/plans/2026-11-01-release-1.5.0.md. Nothing here changes a screen; an item that
turns out to change what a person sees (wording, a snackbar) is shown to the maintainer first. Each fix gets a test
that fails before it. **Test builds:** one Tally Dev APK after batch A (reminders need a real phone: a dead battery,
a battery saver), then the release preview at the end.

**Batches:** A · items 1–3, reminders and notifications · B · items 4–5, speed · C · items 6–8, small fixes ·
D · items 9–10, under the hood · then the release.

## A · Reminders and notifications

- [ ] 1. **A monthly reminder missed on its day comes as soon as the phone is back** · S · fix
      Today `ReminderReceiver.monthlyDate()` skips every day before today, so a loan's monthly day that passed while
      the phone was off (or a battery saver held the alarm) is next reminded a month later. Give it the catch-up the
      daily notices have (`armDaily()`: "due:"/"late:" marks): a monthly day the alarm was armed for that passed
      unshown shows a minute after the re-arm (`BootReceiver` → `schedule()`), without opening Tally. Off for longer
      than a month: one reminder per loan, not one per month missed (maintainer, 2026-11-22).
- [ ] 2. **A loan entered after its monthly day isn't reminded at once** · S · fix
      The other side of 1: only a day the alarm was armed for counts as missed. Today a lend dated a month ago,
      written after today's reminder time, is reminded a minute after saving. Same rule as `armDaily()` ("switching
      it on after its time doesn't").
      Proving check for 1–2: a JUnit test for `monthlyDate` (31st in short months, `since`, shown today, armed vs.
      not armed). Tally has no Java tests yet: add JUnit as `testImplementation` and `./gradlew test` to CI; the
      `fdroid` job must stay green (a test dependency must not change the APK or F-Droid's build).
- [ ] 3. **Notification wording the same in every language** · S · fix
      `n_payback_today`/`n_payback_was` and `n_due_today`/`n_due_was` say the same thing in English but differ in
      French and Turkish (and Chinese mixes the old "payback" word): make them one pair in every
      `values*/strings.xml`, with the word each language's glossary uses (`l10n/glossary/`). Then ask for the
      native-speaker check of the 1.5.0 texts (translators, through the issues); it doesn't hold the release back.

## B · Speed with big notebooks

- [ ] 4. **History draws only what is in view** · M · fix
      Today History draws in chunks of `HIST_CHUNK` (300) and an edit far down redraws every row above it (~250 ms
      for a redraw, ~290 ms for an edit, at 2,900 rows; docs/plans/2026-11-13-release-review-fixes.md). Draw only the
      months near the view, keeping the pinned month heading, the place after an edit (`landFocus`), selection,
      Select all and TalkBack's entry count right. Proving check: a timing test at 3k and 10k entries, and the
      History, search, archive and layout suites unchanged.
- [ ] 5. **Search's first keystroke under 80 ms at 5–10k entries** · S–M · fix
      Measured at 106–148 ms. Profile first (word breaks, folding, suggestion counts), then cache what doesn't
      change between keystrokes. Proving check: a timing test at 5k and 10k entries.

## C · Small fixes

- [ ] 6. **One search fills one recent-search slot** · S · fix
      `recentKeep()` and `recentKeepSug()` (search.js) can each keep the same search, as words and as a
      suggestion; keep one. Test in the search suite.
- [ ] 7. **Undo for an asset's new value** · S · fix
      `saveAsset()` (sheets.js) commits without `withUndo()`; give a changed value the usual "Saved" and Undo.
- [ ] 8. **Deleting a row deep in Home's Year list keeps the place** · S · fix
      As History does (`rowsAround()` / `landFocus()`).

## D · Under the hood

- [ ] 9. **Type checking as a guardrail** · M · its own plan
      TypeScript's checker over the existing JavaScript (`checkJs`, `tsc --noEmit` in lint and CI), one declaration
      file for the shared globals, the saved data and the `Android` bridge, JSDoc where the checker needs it. No `.ts`
      files, no build step, nothing that runs changes; the F-Droid recipe stays as it is. Default mode first (232
      problems on 2026-11-13), strict later, file by file.
- [ ] 10. **Code and tests** · M · cleanup
      One spending-rule helper for `dayGroups`; near-copies merged; file splits (`rows.js`, `addons.js`,
      `settings.js`); the layout suite faster (screenshots only for problems, no fixed sleeps, sharded); shared test
      scaffolding in `harness.js`; `theme.js` tested; the gaps in `tests/dead-code.js` closed.
